## 0. 最重要：環境の見分け方（ローカル / クラウド）

Macのデスクトップアプリ/スマホ/webのどれで開いても、**中で動く実行環境は「ローカル(Mac)」か「クラウド(Linuxコンテナ)」の2種類**ある。**Codexやローカルファイル操作はローカルでしか動かない。**

判定は Claude にコマンドを叩かせるのが確実：

| コマンド | ローカル(Mac) | クラウド |
|---|---|---|
| `uname -a` | `Darwin ...` | `Linux ...` |
| `which codex` | パスが出る | `not found` |
| `echo $HOME` | `/Users/nil-origin` | `/root` 等 |

- **スマホ/webから始めたセッションはクラウドになる**（Macとは別マシン。Macのファイルもcodexも触れない）。
- 既存のクラウド会話を後からMacで開いても**環境は移らない**。ローカル作業は**Mac側で新規セッションを立てる**（デスクトップでローカルフォルダを開く／ターミナルで `claude`）。
- クラウド↔ローカルの橋渡しは **GitHub経由**（クラウドでコミット → Macで `git pull`）。本書もその方法で渡している。

**このフェーズ4（Codex連携）は必ずローカルセッションで行うこと。**

## 2. フェーズ1：Kindle自動スクショ（実機Mac / 完了済み）

### 2.1 前提設定
- Kindleアプリ（Mac版、正式名は **「Amazon Kindle」**）を**見開き2ページ表示＋フルスクリーン**にし、**最初のページ（表紙）**を表示。
- ターミナルに **画面収録** と **アクセシビリティ** の権限を許可（システム設定→プライバシーとセキュリティ）。初回のみ。

### 2.2 撮影範囲（座標）
- `⌘+Shift+4` で本文の左上・右下を計測。**上段の数字＝X、下段＝Y**。
- 実測：左上 `(600, 60)` / 右下 `(1950, 1070)` → `screencapture -R x,y,w,h` 用に **`REGION="600,60,1350,1010"`**（w=1950-600, h=1070-60）。
- ※フルスクリーン＋同一モニタ前提。表示モード/モニタを変えたら測り直す。

### 2.3 撮影スクリプト（本番。ターミナルに貼るだけ）
```bash
rm -f ~/kindle_shots/*.png
( open -a "Amazon Kindle" 2>/dev/null || open -a "Kindle" )   # アプリ名の揺れに両対応
sleep 4                                                        # フルスクリーンのSpaceに戻る待ち
for i in $(seq -w 1 148); do
  screencapture -x -R "600,60,1350,1010" ~/kindle_shots/page_$i.png
  osascript -e 'tell application "System Events" to key code 124'   # →キーで次の見開きへ
  sleep 2
done
open ~/kindle_shots
```
- `key code 124` = 右矢印。`sleep 2` は描画待ち。
- 枚数：289ページ ＝ 表紙(1) + 見開き(144) = **145枚**。`148` は余裕分で、**末尾3枚が最終ページのダブり**になる → 削除：
```bash
rm ~/kindle_shots/page_146.png ~/kindle_shots/page_147.png ~/kindle_shots/page_148.png
ls ~/kindle_shots | wc -l   # 145 になればOK
```

### 2.4 ダブルクリック運用版（任意）
デスクトップに置くと毎回コード不要。`~/Desktop/Kindle本番撮影.command` などに上記ループを入れ、`chmod +x` して使う。テスト用に `PAGES=3` 版も作ると安全（まず3枚で本文が入るか確認 → 本番）。

## 3. フェーズ2：OCRでMarkdown化（Cowork / 完了済み）

**API課金なし**で、ローカルのCoworkにフォルダを渡して全自動で書き起こす。Coworkに以下を依頼：

> `~/kindle_shots` の画像を、ファイル名の若い順（`page_001.png`〜`page_145.png`）に1枚ずつ読んで、各画像は**見開き2ページ分**なので**左ページ→右ページ**の順に、問題文・選択肢・解答/解説をそのままMarkdownに書き起こして `~/gken_text.md` に追記して。推測で補完せず、読み取れた文字だけ。多いので必要なら数回に分けてOK。

- G検定は横書き（左→右読み）なので「左→右」でよい。
- `page_001` は表紙（片側余白）。書ける部分だけでOK。
- なぜ手貼り不要か：claude.aiのチャット窓はファイル読取不可＆添付枚数制限があるため手貼りが要るが、**Cowork/ローカルはフォルダを直接読める**ので全自動化できる。

## 4. フェーズ3：解答付き問題集の生成（Cowork / 完了済み）

`gken_text.md` を元に、Coworkへ以下を依頼して `~/Downloads/gken_問題集_解答付き.md` を作成済み：

> `~/gken_text.md` を元に**解答付き問題集**を作り直して `~/gken_問題集_解答付き.md` に保存して。要件：
> - 問題ごとに1ブロック（**問題番号→問題文→選択肢(ア/イ/ウ/エ等はそのまま)→正解→解説**）
> - **選択肢は全部残す**（削らない）
> - 各問末に「**正解：◯**」と「**解説：**」を明記。正解・解説が別ページ/巻末なら正しく突き合わせる
> - 章・分野の見出しは残す
> - **勝手に創作しない**。読めない箇所は `（判読不能）` と明記
> - 全問終わったら「問題数」と「判読不能一覧」を報告

**解答隠しの演習版が欲しい場合**（後日）：
> `~/gken_問題集_解答付き.md` から各問の「正解」と「解説」を末尾の別セクションに移し、本文側は問題文＋選択肢だけにした `~/gken_演習用.md` を作って。

## 5. フェーズ4：演習Webアプリ（← いまここ。ローカルで続行）

### 5.1 ゴール
`gken_問題集_解答付き.md` を読み込み、**選択式で解答→採点→復習→苦手可視化**するWebアプリ。運用は **Codex構築 ↔ Claudeレビュー** のループ。

### 5.2 要件（v1で確定・叩き台）
- md読み込み（ファイル選択/ドラッグ/貼り付け）→ `問N`/選択肢/`正解`/`解説` を自動解析
- 選択肢タップで解答 → **最後に一括採点**
- 結果：正答数・正答率・**各問の○×／自分の解答／正解／解説**、**間違いだけ絞り込み**
- **複数回の履歴を保存**（localStorage）→ **苦手ランキング**（間違い率順）＋**章別正答率**
- モード：全問／シャッフル／出題数指定／**間違いだけ復習**／**苦手だけ演習**
- 記録のJSONエクスポート・インポート・消去
- 端末内保存のみ・レスポンシブ・ライト/ダーク対応

**追加候補（未確定・要判断）**：通読専用ビュー（全問の問題＋正解＋解説一覧）、解答タイマー、分野タグ、間隔反復。

### 5.3 現状のベース
- **v1あり**：同フォルダ `gken_quiz_v1.html`（単一HTML・インラインCSS/JS・localStorage・mdローダー）。ブラウザで開き `gken_問題集_解答付き.md` を読ませれば動く。
- Artifact URL：<https://claude.ai/code/artifact/924c55ed-82e7-46ca-9581-73ecb36fabf8>
- 方針：**(A) v1をCodexに改良させる（最短）** or **(B) 仕様から新規ビルド**。

### 5.4 mdフォーマット（パーサ実装の要）
```
## 第1章 人工知能とは
### 問1
（問題文）

- ア. 選択肢1
- イ. 選択肢2
- ウ. 選択肢3
- エ. 選択肢4

**正解：イ**
**解説：** （解説文）
```
**許容する揺れ**：全角/半角コロン（：/:）、`ア.`/`ア、`/`(ア)`/`①`、`正解`/`解答`/`正答`、複数正解（`正解：ア・ウ`）、章=`##`・問=`###`。読めない問題は**除外＋一覧報告**（採点を壊さない）。

### 5.5 v1の設計メモ（踏襲/改良の参考）
- 画面：ホーム（読み込み＋モード選択）／演習（1問ずつ）／結果（採点＋レビュー）／統計（苦手・章別・保存）。
- 保存：`localStorage['gken_quiz_stats_v2']` ＝ `{version, perQ:{[qid]:{seen,wrong,chapter,num,preview,hist[]}}, sessions:[]}`。
- 問題ID(`qid`)＝`章|問番号|本文先頭60字`のハッシュ（md再読込でも安定）。
- 複数正解は選択集合の完全一致で採点。未回答＝不正解。
- 既知の弱点：OCR揺れが大きいとパース漏れの可能性 → §5.4の許容範囲を広げる余地。**実mdでの「認識数」を必ず検証**。

### 5.6 運用ループ
1. `prompt.md`（仕様書）を用意 → 2. `codex exec` で構築 → 3. ブラウザで**実mdを読み込んで動作確認** → 4. Claudeにレビュー依頼 → 5. 修正点を反映して再構築。

### 5.7 Claudeレビュー観点
- パーサが**実mdの全問を拾えるか**（認識数＝期待問数か、読めない問題の一覧）
- 単一/**複数選択**の正解判定
- 採点・○×・解説表示・「間違いだけ」絞り込みの正確さ
- localStorage永続化、苦手ランキング（2回以上×間違い率）、章別集計
- モバイル操作性、ダークモード、キーボード/フォーカス、アクセシビリティ

## 8. つまずきポイント（既知の落とし穴）

- **アプリ名は「Amazon Kindle」**。`tell application "Kindle" to activate` は `-1728`（取り出せない）で失敗した。`open -a "Amazon Kindle" || open -a "Kindle"` で両対応にして解決。
- **フルスクリーンは独立Space**になるため、`.command`ダブルクリックでTerminalが別Spaceで開き引きはがされる。→ スクリプト冒頭で対象アプリを`activate/open -a`し、`sleep 4`でSpace復帰を待てば、`screencapture`は表示中のKindleを撮れる。最初の数枚がズレるなら`sleep`を5〜6に増やす。
- **座標の読み方**：`⌘+Shift+4` の数字は上段=X・下段=Y。`screencapture -R` に渡すのは「左上(x,y)＋幅w＋高さh」。右下座標そのままではなく引き算でw,hに直す。
- **2ページ表示だと`→`が2ページ送り**：289ページ→表紙(1)+見開き(144)=145枚。`PAGES`は余裕を持たせ末尾ダブりを削除。
- **権限**：Terminalに「画面収録」「アクセシビリティ」が無いと、真っ黒/ページが送られない。
- **手貼り不要の条件**：ローカルのCowork/Claude Codeは**フォルダを直接読める**ので全自動。claude.aiチャット窓は不可（手貼り＋枚数制限）。
- **環境の勘違い**：スマホ発＝クラウド（Linux）。Codexが要る作業はローカル（Darwin）で。判定は§0。
- **OCR品質**：正解・解説が別ページ/巻末にある本だと突き合わせミスが起きやすい。通読時に軽く検証し、怪しい問だけ元スクショ（`page_◯.png`）で確認。
